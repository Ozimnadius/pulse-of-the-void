# Работа в проекте «Пульс Пустоты»

## Начало работы

Начинай с [README](README.md). Открывай [журнал](docs/ЖУРНАЛ.md) по теме задачи. Для сведений о мире используй [указатель источников](ИСТОЧНИКИ.md). Расхождения между документами и игрой проверяй по исходникам или сборке. Перед изменением файлов посмотри `git status --short`.

## Кто ведёт записи

- Чат, в котором пользователь принял решение, записывает его в журнал в тот же ход. Для важного предложения, которое пользователь попросил сохранить, используй пометку «Предложено». При пересмотре добавь датированную запись со ссылкой на прежнее решение.
- Чат, выполнивший шаг, записывает результат существенной проверки. При закрытии этапа он же фиксирует итог, что проверено, что осталось открытым, и даёт ссылку на подтверждение. Родитель обновляет общий план и ссылается на запись. Достаточно одной записи на одно событие.
- Тот же чат обновляет README, когда меняются запуск, возможности доступной версии, известная проблема или точка продолжения. При старте согласованного этапа укажи в README его название и чат. При завершении замени эту строку актуальным состоянием.
- В ходе обычной работы фиксируй сведения, которые изменят действия следующего разработчика. Перечень команд и промежуточную переписку оставляй в чате. Записи по лору сопровождай ссылками на источник, придуманные для игры детали обозначай как авторские.

## Как вести журнал

Добавляй запись под датой события. Указывай статус («Принято», «Предложено», «Проверено» или «Открыто»), суть и причину или результат. Для проверки укажи, что запускали и что наблюдали. Если существенная часть осталась непроверенной, назови её. Ссылки на чат, кадр, видео или коммит добавляй там, где они помогут восстановить контекст.

## Кто делает коммит

Исполнитель коммитит законченный и проверенный согласованный шаг вместе с относящимися к нему записями. Отдельное принятое решение можно зафиксировать коммитом документации. Перед коммитом проверь затронутое поведение, ссылки изменённых документов, `git diff --cached` и `git diff --cached --check`. Подготавливай файлы своего шага по именам. Изменения пользователя и других чатов сохраняй отдельно.

Сообщение оформляй по Conventional Commits с кратким описанием по-русски, например `docs(game): записать решение о ремонте корабля`. Работа ведётся в локальном Git. Для публикации требуется отдельное поручение пользователя.
